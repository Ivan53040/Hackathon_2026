# PART 1 — 五秒測試

同一個專案有**兩個五秒**，考的東西完全不同。

## 1A　台上那五秒（觀眾）

一個陌生人抬頭看螢幕五秒。他能回答嗎？

| # | 問題 | 現況 | 判定 |
|---|---|---|---|
| S1 | 這是什麼？ | 兩座塔、兩個人 | ⚠️ 塔在投影機上是 1.24:1，可能整個看不到 |
| S2 | 他們在幹嘛？ | 互相丟東西 | ⚠️ 敵我兩色亮度差 1.03，分不出誰打誰 |
| S3 | 為什麼我該在意？ | 「他動不了，而且有東西朝他飛過去」 | ❌ **法陣在 VFX 優先度只排第 4** |
| S4 | 我可以做什麼？ | 掃 QR code 自己玩 | ⚠️ 尚未設計 |

**S3 不通過 = 否決。** 這是全場唯一要傳達的訊息，目前沒有任何一個視覺元素在保護它。

## 1B　Landing 那五秒（judge 打開網址）

| # | 問題 | 需要回答成 |
|---|---|---|
| S1 | 這是什麼？ | 一個用**實體筆**在鏡頭前畫符文的對戰遊戲 |
| S2 | 提供什麼？ | 現在就能玩，瀏覽器打開就好 |
| S3 | 為什麼我該在意？ | 你的手真的在空中畫魔法，這不是按鍵 |
| S4 | 下一步？ | **一個主要動作：創建房間** |

> ⚠️ v3 定案「登入頁四顆按鈕：創建房間 / 加入房間 / 說明 / 設定」。
> **四顆平權的按鈕違反 S5（單一主要動作）與 Hick's Law。**
> 建議：創建房間為主按鈕，其餘三個降級為次要樣式。
> 這不是美感問題，是「judge 站在那裡不知道該按哪個」的問題。

# PART 2 — 問題清單

每個問題回答：**是什麼 · 為什麼是問題 · 影響誰 · 多嚴重 · 怎麼知道解決了**

## 🔴 P0-1　觀眾看不出「他在施法」

| | |
|---|---|
| **是什麼** | 施法定身的 0.8–1.5 秒是全遊戲的核心張力，但視覺上只有一個地面圓環 |
| **為什麼是問題** | 這是唯一讓觀眾產生情緒的時刻。看不到它，demo 就只是「兩個方塊互丟東西」 |
| **影響誰** | 觀眾、judge |
| **多嚴重** | **致命。** 這是專案存在的理由 |
| **怎麼知道解決了** | 10 公尺外、投影機上，非團隊成員能指出「那個人現在不能動」 |

## 🔴 P0-2　敵我不分

| | |
|---|---|
| **是什麼** | 金 (L=0.513) 與青 (L=0.501) 亮度差 3%，投影機過曝與 bloom 會抹平色相 |
| **為什麼是問題** | 觀眾分不出誰打誰，就無法追蹤勝負 |
| **影響誰** | 觀眾、色覺異常者（約 1/12 男性） |
| **多嚴重** | **致命** |
| **怎麼知道解決了** | 螢幕截圖轉灰階後，仍能分辨雙方所有元素 |

## 🔴 P0-3　玩家看不懂連續視角瞄準

| | |
|---|---|
| **是什麼** | v3 把三態瞄準改成按住 W/S 的連續 `pitch`，放開不歸零 |
| **為什麼是問題** | v2 就把「玩家看不懂瞄準」列為**機率高、影響高**的風險。v3 讓它更難懂——三段虛線至少是離散可讀的，連續射線不是。而且**放開不歸零**代表玩家會迷失在某個角度 |
| **影響誰** | 每一個第一次玩的人，包含排隊的 judge |
| **多嚴重** | 高。玩家 30 秒內學不會就會放棄 |
| **怎麼知道解決了** | 陌生人在 30 秒內成功打中特定樓層，且說得出自己瞄哪一層 |

## 🔴 P0-4　「自己的牆擋自己」看起來像 bug

| | |
|---|---|
| **是什麼** | v3 規則 C2：在自己的牆後面開火，法術被自己的牆擋住，魔量照扣 |
| **為什麼是問題** | 這是 v3 最深的機制（「蓋牆＝安全但打不到人」），但玩家第一次遇到只會覺得「我明明打出去了，這遊戲壞了」 |
| **影響誰** | 所有玩家 |
| **多嚴重** | 高。它同時是**最好的機制**和**最像 bug 的機制** |
| **怎麼知道解決了** | 玩家第一次撞到自己的牆之後，第二次會主動走出牆外再開火 |

## 🟡 P1-1　頭頂數值在投影機上讀不到

v3 把 HP/MP 移到角色頭頂，等於畫面多了 4 組數值 + `???` 狀態，全部貼在會移動的小角色上。
D4 已裁決用格子不用數字，但**尺寸、位置、被塔遮擋**都還沒解。

## 🟡 P1-2　`???` 遮蔽狀態要一眼看懂

「我看不到他的血量」是一個**新的資訊狀態**，v3 沒有定義它長什麼樣。
用文字 `???` 是最弱的解——它需要閱讀，而閱讀在 10 公尺外不成立。

## 🟡 P1-3　換樓層沒有回饋

v3：走到最左端**停留** `FLOOR_EDGE_HOLD_MS` 才下樓。
停留期間畫面上什麼都沒發生 → 玩家會以為卡住了，然後放開。

## 🟡 P1-4　校準頁沒過就沒有人玩

judge 排隊試玩時，校準是**第一個**也是**唯一**可能勸退他的地方。
30 秒沒成功，他就走了，而且他會記得「那個東西弄不起來」。

## 🟢 P2-1　施法失敗的兩難

對玩家要溫和（不能羞辱），對觀眾要明顯（失敗是戲劇性的）。
D4 已裁決站觀眾那邊，但**不能變成嘲笑**。

## 🟢 P2-2　沒有 HTTPS 時 Landing 會神秘失敗

`getUserMedia()` 在非安全環境直接拋錯。若 judge 用 `http://` 開網址，
畫面不會說明原因，只會壞掉。**需要一個明確的錯誤狀態**（見 Stage 2 的 U3）。

# PART 3 — 疑慮地圖

每個疑慮都必須有一個畫面元素負責回答它。沒有的話，那是**裝飾過的**設計，不是**為說服而做的**設計。

| 疑慮 | 誰有 | 什麼回答它 | 目前有嗎 |
|---|---|---|---|
| 「這只是 CV demo，遊戲性很差」 | judge | 猜拳循環要**在 demo 裡真的演出來**：他開盾 → 我改閃電 → 他蓋牆 → 我繞位 | ⚠️ 靠劇本，沒有視覺保證 |
| 「辨識大概很爛，這是剪過的吧」 | judge | **webcam PIP 全程可見** + 現場真的操作 | ✅ v3 已規定保留 |
| 「我畫不出來會很尷尬」 | 排隊試玩的人 | 校準頁步驟 2 先成功一次 + 失敗反饋不羞辱 | ✅ 部分 |
| 「這要裝什麼嗎？」 | 所有人 | 零安裝、掃 QR 就能玩 | ⚠️ Landing 要講出來 |
| 「看不懂在幹嘛」 | 觀眾 | 那句三秒訊息 | ❌ **P0-1 未解** |

# PART 4 — 信任階梯

hackathon 版本，由弱到強。**這些必須是真的，不准生成。**

```
線上網址可自己試  →  webcam PIP 全程可見  →  現場真的在玩（不是影片）
                  →  遙測數字「N 次施法，辨識率 X%」
```

最強的那一階是**現場真的在玩**。所有設計都不該削弱它——
這也是為什麼 webcam PIP 不能被藏在角落，它是證據。

> ⚠️ **遙測數字必須是真的。** 編造的數字是 B10 誠信問題，不是設計問題。
> 後端已規劃 `/api/telemetry/summary`，用它跑出來的數字。

# PART 5 — 不是問題的東西（Keep it）

**不要為了重新設計而重新設計。** 這幾條 v3 已經對了，不准動：

| 已經對的 | 為什麼別動 |
|---|---|
| **鏡頭永遠不動** | 為了觀眾犧牲玩家，是正確的取捨（也是 D4 的先例） |
| **webcam PIP 保留** | 它是信任階梯最強的那一階 |
| **暖金 / 冷青的方向** | 符文對夜空 10.6:1，色彩方向的核心是對的，要修的是亮度差與建築對比 |
| **符文吸附特效** | 「系統認得我，而且把我畫得更好看」——這是最值錢的 30 行 |
| **失敗不出現「辨識失敗」四個字** | 對的。玩家自己知道錯了 |
| **深夜天文台的美術方向** | 有原創性，不是霓虹賽博。保留 |

# 結論：P0 排序

設計時間應該照這個順序花：

```
1. 法陣 —— 讓觀眾看到「他動不了」          (P0-1)
2. 敵我識別 —— 加第二層編碼               (P0-2)
3. 瞄準指示器 —— 讓玩家看懂連續視角        (P0-3)
4. 自己的牆擋自己 —— 讓它看起來像規則不像 bug (P0-4)
```

**這四件事解決了，這個 demo 就成立。其他全部是加分。**
