# 動畫計劃 — Higgsfield 生成 × 即時遊戲

> 規格 v5 · 三人分工 · 對應 [`PLAN.md`](./PLAN.md) §5 與 [`WORKSPLIT.md`](./WORKSPLIT.md)
> **開工前所有人先讀第 0 節。跳過它會浪費一整批生成額度。**

---

## 0. 先講清楚：Higgsfield 生的是影片，不是遊戲動畫

```
❌ 不能做的事
   生一段「法師施法」的影片 → 直接放進遊戲
   為什麼：對手要對遊戲狀態即時反應。他什麼時候起手、
          什麼時候被打中、往哪邊閃，都是玩家決定的，不是預錄的。

✅ 能做的事
   生影片 → 抽格 → 貼成 sprite sheet → 遊戲依狀態切換播放
   為什麼：第一人稱下對手是遠處一個固定角色，
          做成 billboard sprite 完全可行（早期 DOOM 就是這樣）。
```

**第一人稱是這件事能成立的唯一前提。** 第三人稱要各種角度，AI 生的素材會對不起來；
第一人稱只需要**一個正面角度**。這是 v5 意外送給你們的禮物。

### 三條不可協商的架構規則

1. **`opponent.ts` 從 `public/anim/manifest.json` 讀 sprite atlas。**
   一開始就用**程式畫的佔位剪影**上線，素材後到再換。
   → 生成失敗 / 來不及 / 品質不行，遊戲照樣能玩。**這是保命設計。**
2. **相機、拖尾、吸附、HUD、投射物軌跡一律程式做，不准用生成素材。**
   它們必須跟遊戲狀態逐幀同步，影片做不到。
3. **PvP 雙方看到的對手是同一組素材。** 你只會看到對手，不會看到自己 →
   **只要生一套角色，不用生兩種顏色。工作量直接砍半。**

## 2. 類 A — 對手角色（人員 1）　★ 最重要

### 2.1 一定要先做的一步：角色定裝

> ⚠️ **AI 生成最大的風險是「每一段的角色長得不一樣」。**
> 解法：**先生一張角色參考圖，之後所有動作都用 image-to-video 從這張圖出發。**
> 不要每個狀態各自從文字生成——那會生出七個不同的人。

**Step 1 — 角色參考圖（只生一次，全隊確認過才往下走）**

```
prompt:
full body wizard duelist standing facing camera, dark hooded robe,
holding a slender wand in right hand, dramatic rim light from behind,
plain solid black background, centered, full figure head to feet,
cinematic lighting, no text, no logo

設定：9:16 直幅 · 單一角色 · 純黑背景（★ 這一條不准改，去背要靠它）
```

**驗收角色圖**：站到 3 公尺外看螢幕，剪影認得出是「一個拿杖的人」→ 過。
認不出來就重生，**不要將就**——後面七段全部建立在這張圖上。

### 2.2 七個狀態

用同一張參考圖做 image-to-video，每段 **2–3 秒**就夠。

| # | 狀態 | 遊戲裡什麼時候播 | 生成 prompt 重點 | 抽格數 |
|---|---|---|---|---|
| **S1** | `idle` | 平常 | 極輕微的呼吸與衣袍飄動，**腳不移動** | 12（loop） |
| **S2** | `charge` | 對手按下起手 | **舉杖過頭**，動作要大要清楚 | 8 |
| **S3** | `cast_loop` | 對手畫符文中 | 杖尖在空中畫圈，可 loop | 8（loop） |
| **S4** | `release` | 對手放出法術 | 杖往前刺，快 | 6 |
| **S5** | `dodge` | 對手側身閃避 | **整個身體向側傾**，不是走路 | 6 |
| **S6** | `hit` | 對手被打中 | 上半身向後折，衣袍炸開 | 8 |
| **S7** | `down` | 對手死亡 | 向前倒下，杖脫手 | 12 |

**S2 是最重要的一段。** 它是玩家唯一的預警——看到對手舉杖，你才知道要準備閃。
**這一段值得多生幾次挑最好的。**

### 2.3 生成參數（全部固定，不要每段改）

```
比例      9:16 直幅
時長      2–3 秒
背景      純黑，全程不變
鏡頭      完全固定，不准有推軌、環繞、變焦     ← ★ 最容易錯的一條
角色位置  畫面正中，全身入鏡，腳不出框
光線      背後輪廓光為主，正面補光極弱
```

> 🔴 **「鏡頭固定」是最容易被 AI 忽略的指令。** 生出來的片如果鏡頭有推移，
> 抽格之後角色會在 sprite sheet 裡漂來漂去，遊戲裡看起來像在滑冰。
> **每一段生完先確認：把第一格跟最後一格疊起來，地面線有沒有跑掉。**

### 2.4 抽格 → sprite atlas

```bash
# 1) 抽格（依上表的張數，平均分佈）
ffmpeg -i S2_charge.mp4 -vf "fps=12,scale=-1:384" frames/S2_%03d.png

# 2) 去背：純黑底 → alpha（用 ImageMagick）
mogrify -fuzz 12% -transparent black frames/S2_*.png

# 3) 併成一張橫向 atlas
montage frames/S2_*.png -tile x1 -geometry +0+0 -background none S2_charge.png
```

**輸出規格（不准改，D 的 `opponent.ts` 依這個寫）**

```
單格尺寸    256 × 384 px
排列        橫向一列
檔名        public/anim/S{n}_{name}.png
色彩        PNG-8 帶 alpha（檔案小很多，遠處看不出差）
總預算      全部 7 個狀態加起來 ≤ 3 MB
```

### 2.5 `manifest.json`（人員 1 交付給 D）

```jsonc
{
  "frameW": 256, "frameH": 384,
  "states": {
    "idle":      { "file":"S1_idle.png",     "frames":12, "fps":10, "loop":true  },
    "charge":    { "file":"S2_charge.png",   "frames":8,  "fps":24, "loop":false },
    "cast_loop": { "file":"S3_cast.png",     "frames":8,  "fps":12, "loop":true  },
    "release":   { "file":"S4_release.png",  "frames":6,  "fps":30, "loop":false },
    "dodge":     { "file":"S5_dodge.png",    "frames":6,  "fps":24, "loop":false },
    "hit":       { "file":"S6_hit.png",      "frames":8,  "fps":24, "loop":false },
    "down":      { "file":"S7_down.png",     "frames":12, "fps":15, "loop":false }
  }
}
```

> **fps 對應 [`PLAN.md`](./PLAN.md) §5.1 的動畫時長。**
> 例：`charge` 8 格 ÷ 24fps = 0.33s，接近規格的 0.25s。**對不上就改 fps，不要改遊戲。**

## 3. 類 B — 法術與特效（人員 2）

### 3.1 關鍵技巧：純黑背景 + 加色混合

Higgsfield 不輸出 alpha 通道。但**發光的東西不需要 alpha**：

```
在純黑背景上生成 → 遊戲裡用加色混合（additive / screen）貼上去
黑色部分自動變透明，亮的部分自然發光。
```

**火焰、火花、閃電、魔法光暈全部適用。** 煙霧與實體碎片不適用（它們需要真的 alpha）。
→ **所以：不要生煙，只生光。**

### 3.2 素材清單

| # | 素材 | 用在哪 | prompt 重點 | 規格 |
|---|---|---|---|---|
| **F1** | 攻擊飛行 loop | 投射物本體 | 一團緊實的橘金火球，**純黑底**，原地燃燒不移動 | 8 格 · 128² |
| **F2** | 牆升起／破碎 | 遮蔽物 | 石塊從地面長出、被打碎成塊，純黑底 | 10 格 · 192² |
| **F3** | 命中爆散 | 打中你的瞬間 | 從中心向外炸開的光與火花，純黑底，**0.3 秒內結束** | 12 格 · 256² |
| **F4** | 符文點燃 | 吸附完成後 | 金色線條被點燃、化成火星，純黑底 | 10 格 · 256² |

> **不要生「符文的形狀」。** 符文形狀是玩家畫的，必須程式繪製。
> F4 只生「點燃的火星質感」，疊在程式畫的線上。

```
共用生成參數：純黑背景 · 鏡頭固定 · 物體置中 · 無文字無 logo
比例 1:1 · 時長 1–2 秒
```

### 3.3 交付

```
public/anim/fx/F1_attack.png  F2_wall.png  F3_impact.png  F4_ignite.png
public/anim/fx/manifest.json    ← 格式同 §2.5
```

## 6. 風險與 Kill List

| 風險 | 機率 | 影響 | 對策 |
|---|---|---|---|
| **七段角色長得不一樣** | **高** | 高 | §2.1 定裝流程。**全部從同一張參考圖 image-to-video** |
| 生成的鏡頭在動 | **高** | 高 | 每段生完疊第一格與最後一格檢查地面線 |
| 去背後邊緣有黑邊 | 中 | 中 | `-fuzz` 調到 12–18%；或改用加色混合（發光素材不需要去背） |
| 額度／時間不夠 | 中 | 高 | 照 A → B → C 的順序做，**C 隨時可砍** |
| sprite 太大掉 fps | 低 | 中 | 單格 ≤ 256×384，總量 ≤ 3MB，PNG-8 |
| 素材根本沒到 | 中 | **低** | ✅ **佔位剪影本來就能玩**，這是架構保護的 |

### Kill List（按順序砍）

1. **砍類 C**（背景板改用純色漸層，Landing 用截圖）—— **只影響好看，不影響能玩**
2. **砍 S5 dodge / S7 down**，用程式做位移與淡出代替
3. **砍類 B**，法術特效全部改程式粒子（D 兩小時可以做完）
4. **只保留 S1 idle + S2 charge + S6 hit 三個狀態** —— 這三個撐得住整場對戰
5. **全部砍掉，用程式剪影** —— 遊戲仍然完整，只是樸素

> **⚠️ 唯一不准砍的是 B4 demo 備援影片。** 那是台上炸掉時的最後防線。

## 7. 給三位的一句話

**你們生的不是「動畫」，是「對手」。**

玩家在這個遊戲裡看不到自己，整個 90 秒他只看著一個人——就是你們生出來的那個。
他舉杖的那 0.25 秒，是玩家決定要不要閃的全部依據。

**把 S2 `charge` 做好，其他都可以將就。**
