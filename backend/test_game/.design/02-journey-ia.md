# PART 1 — 兩條旅程

## 1A　觀眾的 90 秒（不能互動，只能看）

```
0:00  抬頭        → 要看到：兩塊場地、兩個人、誰是誰
0:05  第一個法陣   → 要看到：他正在準備什麼
0:07  符文成形     → 要看到：他畫出了一個形狀
0:08  攻擊飛出     → 要看到：那是他打出去的
0:09  命中 / 被牆吃 → 要看到：中了還是被擋了
0:20  蓋牆         → 要看到：他躲起來了，而且我看不到他了   ★ 情緒起點
0:35  走出牆外開火  → 要看到：他為了開火冒險了              ★ 最好的一刻
1:20  擊殺         → 要看到：結束了，誰贏
```

**★ 標記的兩個瞬間是整場 demo 的價值所在。** 設計預算應該不成比例地壓在這兩點上
（Peak-End：體驗由最強的一刻與結尾決定，不是平均分配）。

## 1B　玩家的旅程

```
Landing ──┬── 創建房間 ──┐
          ├── 加入房間 ──┤
          ├── 說明       │
          └── 設定       │
                         ▼
            ⚠️ 校準（強制，在進房間之前）
                         ▼
                     房間大廳
                         ▼
                       對戰
                         ▼
                       結算 ──▶ 再來一場
```

**校準必須在進房間之前。**
兩人進房才發現一方追蹤不到，這場就廢了還要重新配對。

**「再來一場」不回校準。** 已經校準過了，再來一次是懲罰。

# PART 2 — 對戰畫面的資訊層級 ★ 核心

這是整個設計裡唯一真正困難的部分。

Miller's Law：**半秒內能讀的階層只有三層。** 所以資訊必須分成三層，且視覺權重差距要夠大。

## Layer 1 — 半秒內，給觀眾

| 資訊 | 視覺載體 | 權重 |
|---|---|---|
| **誰躲著、誰走出來了** | 牆的位置 + 角色相對於牆的位置 | **最高。這是 v4 的核心** |
| 誰在準備施法 | 法陣（跟著角色走的地面光環） | 高 |
| 有東西在飛 | 投射物 + 拖尾 | 高 |
| 誰快死了 | HP 格子 | 高 |
| 誰是誰 | 暖金 / 冷青 + **填實/描邊** | 高（永遠在） |

> **Layer 1 必須在灰階、投影機過曝、10 公尺距離三種條件下同時成立。**

## Layer 2 — 兩秒內，給玩家

| 資訊 | 視覺載體 |
|---|---|
| 我在哪、對手在哪 | 角色位置（鏡頭固定，所以位置本身就是資訊） |
| 場上有哪些牆、誰的 | 牆的實體 + owner 色 + **自己的牆對自己半透明** |
| **我現在打不打得到他** | 我與他之間有沒有牆——**看不到他就是打不到他** |
| 我的 MP 夠不夠 | MP 格子，快滿時發亮 |

> ★ v4 拿掉瞄準之後，Layer 2 只剩「位置關係」。
> **這正是我們要的**——玩家要想的只有一件事：走出去，還是留在牆後。

## Layer 3 — 需要時才看

| 資訊 | 視覺載體 |
|---|---|
| MP 精確值 | **只有自己的、只在接近某招門檻時**顯示數字（D4 唯一站玩家的例外） |
| 剩餘時間 | 小，低對比。時限只是保險，不是主要玩法 |
| 符文小抄 | 常駐但低調（D4：觀眾每 3 秒換一個人在看） |
| webcam PIP | 常駐。它是證據，不是控制項 |

# PART 3 — 五態

**最常被跳過的一塊，因為 mock 永遠只畫快樂路徑。** 每個 surface 都要有這五個狀態。

## Landing

| 狀態 | 設計 |
|---|---|
| U1 空 | 不適用 |
| U2 載入 | 字體與 3D 預覽載入中——**不要用轉圈**，用骨架或靜態插畫 |
| U3 錯誤 | 🔴 **非 HTTPS / 沒有 webcam / 瀏覽器不支援**——必須明確說出原因與解法，不能只是壞掉（P2-2） |
| U4 成功 | 進入校準 |
| U5 極端 | 極慢網路：先給可讀的靜態畫面，3D 後到 |

## 校準頁 ★ 最關鍵的頁面

| 狀態 | 設計 |
|---|---|
| U1 空 | 還沒偵測到手：**告訴他該做什麼**（「把筆舉到鏡頭前」），不是空白等待 |
| U2 載入 | 等待 webcam 權限 → 明確指向瀏覽器的權限提示位置 |
| U3 錯誤 | 權限被拒 / 太暗 / 追蹤率低 → **三種不同訊息，各自帶解法**（「把檯燈轉向自己」） |
| U4 成功 | 步驟 2 畫出三角形 → **成功要慶祝一下**，這是他第一次施法 |
| U5 極端 | 完全沒有 webcam → 直接給滑鼠模式，不要把他擋在門外 |

> **步驟 2 是教學不是校準。** 玩家在這裡學會「按住 Shift 才畫」，之後就不會問。

## 大廳

| 狀態 | 設計 |
|---|---|
| U1 空 | 等對手：**房間代碼要大**，這是他唯一要做的事（唸給旁邊的人聽） |
| U2 載入 | 連線中 |
| U3 錯誤 | 房間不存在 / 房間已滿 → 用後端回傳的 `message`，直接顯示 |
| U4 成功 | 對手加入 → 明確的「兩個人都在了」+ 倒數 |
| U5 極端 | 等超過 60 秒 → 主動提供「改打 bot」 |

## 對戰

| 狀態 | 設計 |
|---|---|
| U1 空 | 不適用 |
| U2 載入 | 開場倒數，同時是「看清楚場地」的時間 |
| U3 錯誤 | **對手斷線 → 「幻影接管」**。一行帥氣的字，然後繼續（後端 §6.2） |
| U4 成功 | 擊殺 → 結算 |
| U5 極端 | 時限到平手 · 雙方同時死 · 場上塞滿 4 面牆 → 都要看起來是刻意的 |

## 結算

| 狀態 | 設計 |
|---|---|
| U4 成功 | 勝負 + **一個數字**（你的辨識率 / 施法次數），這是 Peak-End 的「End」 |
| U5 極端 | 平手 |

# PART 4 — 單一動作

| Surface | 唯一主要動作 | 次要 |
|---|---|---|
| Landing | **創建房間** | 加入房間 / 說明 / 設定（降級樣式） |
| 校準 | **完成當前步驟** | 跳過（給滑鼠模式） |
| 大廳 | **開始** | 改打 bot / 離開 |
| 結算 | **再來一場** | 回大廳 |

> ⚠️ v3 的登入頁四顆平權按鈕違反這一條（見 `01-problem.md` PART 1B）。
> **改成一主三次，不是重新設計，是把主要動作標出來。**

CTA 文案要**說出動作與代價**，不要用「開始」「了解更多」：

```
✗  開始 · 進入 · 了解更多
✓  Create a room          （然後把代碼唸給對手）
✓  Practise against a bot （不需要對手）
```

# PART 5 — 導覽與返回

| # | 規則 | 應用 |
|---|---|---|
| U11 | 隨時知道自己在哪、能去哪 | 校準頁的 `● ○ ○` 步驟指示器；大廳顯示房間代碼 |
| U13 | 一個畫面一個決定 | 校準三步驟拆開，不要一次問完 |
| U14 | 控制項照慣例 | Esc 返回、Enter 確認。**不要重新發明** |
| U15 | 移不掉的複雜度要**刻意搬移** | 追蹤的複雜度搬到校準頁一次解決，對戰中不再打擾玩家 |

**返回路徑必須存在。** 校準頁一定要能退回 Landing——
不然 judge 卡在權限被拒的畫面，就只能重整頁面。

# PART 6 — 待決問題（Stage 3 要解）

**★ v4 把六題砍成四題，而且砍掉的是最難的兩題（瞄準、`???`）。**

1. **掩體的三個時刻怎麼演？**（P0-1）躲起來 / 走出來 / 牆吃下攻擊
2. **敵我的第二層編碼用什麼？** 我傾向填實 vs 描邊，但要在 Stage 3 比較過
3. **「對手消失了」怎麼看起來像規則不像掉線？**（P1-2）牆邊微光？地面殘影？
4. **頭頂數值放哪、多大？**（P1-1）單層之後畫面高度空出很多，這是 v4 的紅利
